# Трекер задач

Сервер реализует всё API, необходимое фронтенду: добавление, просмотр, редактирование, удаление и отметку выполнения задач, правила повторения (`d`, `y`, `w`, `m`), поиск, а также аутентификацию по паролю с выпуском JWT-токена.

## Стек

- Go 1.27, роутер [chi](https://github.com/go-chi/chi)
- SQLite ([modernc.org/sqlite](https://modernc.org/sqlite), чистый Go, CGO не требуется)
- JWT: [golang-jwt/jwt/v5](https://github.com/golang-jwt/jwt)
- тесты: testify (пакет `tests`, чёрный ящик по HTTP)

## Структура проекта

```
cmd/todo     — точка входа: конфигурация из окружения, запуск сервера
pkg/api      — обработчики HTTP, middleware аутентификации, NextDate
pkg/db       — работа с SQLite (схема, CRUD)
web          — готовый фронтенд (не изменяется)
tests        — тесты
Dockerfile   — сборка докер-образа
```

## Переменные окружения

| Переменная      | Назначение                                            | По умолчанию   |
|-----------------|-------------------------------------------------------|----------------|
| `TODO_PORT`     | порт сервера                                          | `7540`         |
| `TODO_DBFILE`   | путь к файлу базы SQLite                              | `scheduler.db` |
| `TODO_PASSWORD` | пароль входа; пусто — аутентификация выключена        | не задан       |

## Запуск локально

```bash
go run ./cmd/todo
```

Открыть в браузере: <http://localhost:7540>

Если задан пароль, фронтенд сам перенаправит на страницу входа `/login.html`;
после ввода пароля в браузер кладётся кука с токеном на 8 часов.

Пример запуска с паролем и нестандартным портом:

```bash
TODO_PASSWORD=12345 TODO_PORT=8000 go run ./cmd/todo
```

## Тесты

Тесты ходят по HTTP в **уже запущенный** сервер, поэтому:

1. Запустите сервер (с паролем, если проверяете аутентификацию):

   ```bash
   TODO_PASSWORD=12345 go run ./cmd/todo
   ```

2. В файле `tests/settings.go` включите проверки по мере реализации фич:

   ```go
   var FullNextDate = true  // полные правила повторения (w, m) — реализованы
   var Search = true        // поиск /api/tasks?search= — реализован
   var Token = `...`        // JWT-токен, если включён TODO_PASSWORD
   ```

   Токен для `Token` можно получить командой:

   ```bash
   curl -d '{"password":"12345"}' localhost:7540/api/signin
   ```

3. Запустите тесты:

   ```bash
   go test -count=1 ./tests
   ```

   Флаг `-count=1` отключает кэш результатов — для тестов, зависящих от внешнего сервера, он обязателен.

⚠️ Тесты предварительно **удаляют все задачи** из таблицы `scheduler`.

## Docker

Сборка бинарника (статический, без внешних зависимостей):

```bash
# для контейнера на Apple Silicon:
CGO_ENABLED=0 GOOS=linux GOARCH=arm64 go build -o todo-arm64 ./cmd/todo

# для x86-64 (Ubuntu, Astra Linux и т.п.):
CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -o todo-amd64 ./cmd/todo
```

В `Dockerfile` имя бинарника в `COPY` должно соответствовать собранной архитектуре
(`todo-arm64` или `todo-amd64`).

Сборка образа и запуск контейнера с базой на хосте:

```bash
docker build -t todo-app .

docker run -d --name todo \
  -p 7540:7540 \
  -v "$(pwd)/docker-data:/app/data" \
  -e TODO_DBFILE=/app/data/scheduler.db \
  -e TODO_PASSWORD=12345 \
  todo-app
```

- `-p 7540:7540` — порт `хост:контейнер` (если 7540 занят, смените внешний);
- `-v .../docker-data:/app/data` — база SQLite живёт на хосте в `./docker-data`
  и переживает пересоздание контейнера.

После запуска открыть <http://localhost:7540>.

Остановка и удаление контейнера:

```bash
docker stop todo && docker rm todo
```

- ✅ Docker-образ с инструкцией по запуску (раздел выше).

## API

| Метод   | Путь               | Назначение                                  |
|---------|--------------------|---------------------------------------------|
| GET     | `/api/nextdate`    | вычислить следующую дату по правилу          |
| POST    | `/api/task`        | добавить задачу                              |
| GET     | `/api/task?id=`    | получить задачу                              |
| PUT     | `/api/task`        | изменить задачу                              |
| DELETE  | `/api/task?id=`    | удалить задачу                               |
| POST    | `/api/task/done?id=` | выполнить задачу (перенос или удаление)   |
| GET     | `/api/tasks`       | список ближайших задач, `?search=` — поиск   |
| POST    | `/api/signin`      | вход, выдача JWT-токена                      |
